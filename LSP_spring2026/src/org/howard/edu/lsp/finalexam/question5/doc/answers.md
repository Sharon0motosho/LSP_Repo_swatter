**Heuristic 1:**

**Name:**

Keep data and behavior together

**Explanation:**

Improves readability by ensuring classes represent real-world entities clearly
Reduces confusion since logic is located with the data it operates on
In lecture, this was emphasized to avoid “data-only classes” and scattered logic


**Heuristic 2:**

**Name:**

Hide implementation details (encapsulation)

**Explanation:**

Prevents misuse of internal methods (like getNextId())
Makes code easier to maintain since internal changes don’t affect other classes
In lecture, this was shown through restricting access with private methods


**Heuristic 3:**

**Name:**

Use meaningful class and method names

**Explanation:**

Makes code self-documenting and easier to understand
Reduces need for excessive comments
In lecture, poor naming examples were contrasted with clear, descriptive names
